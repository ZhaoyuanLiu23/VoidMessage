# 认证、隐私与安全设计

## 安全模型

VOID MESSAGE 的公开匿名不等于服务端无身份。系统用邮箱建立私有账号边界，再将公开可见身份严格缩减为颜色头像。这样既能维持登录状态和消息归属，也不会在房间中暴露邮箱或昵称。

## 密码存储

- 算法：PBKDF2-HMAC-SHA256
- 迭代次数：210,000
- 随机盐：16 字节
- 输出长度：256 bit
- 数据库只保存包含算法、迭代次数、盐与摘要的模块化 password_hash 字符串，不保存明文密码
- 密码比较使用固定时间字节比较，降低时序侧信道风险

生产系统仍建议根据运行环境定期评估参数，并规划向 Argon2id 等内存困难算法迁移。

## 会话管理

- 登录成功生成 32 字节加密安全随机令牌。
- 浏览器持有原始令牌，数据库只保存 SHA-256 摘要。
- Cookie 设置 **HttpOnly** 与 **SameSite=Lax**；HTTPS 环境启用 **Secure**。
- 默认会话有效期为 30 天。
- 退出登录会同时删除数据库会话和浏览器 Cookie。
- API 根据服务端会话解析用户，不能由客户端自行指定消息颜色。

## 防滥用边界

| 场景 | 当前限制 |
| --- | --- |
| 登录尝试 | 每 15 分钟最多 10 次 |
| 同邮箱注册 | 每小时最多 3 次 |
| 房间访问 | 只允许预定义 community 白名单 |
| 颜色写入 | 只允许服务端颜色白名单 |
| 消息返回 | 不返回邮箱、密码字段和会话令牌 |
| 消息顺序 | 由服务端时间与 ID 决定 |

## 数据最小化

公开消息响应为：

~~~json
{
  "id": 128,
  "body": "今天也完成了训练。",
  "color": "#22d3ee",
  "createdAt": 1787577600,
  "mine": false
}
~~~

其中 **mine** 由当前会话与消息作者在服务端比较后产生。公开响应不包含邮箱、用户 ID、密码摘要、盐或会话信息。

## 已知边界

- 当前未提供邮箱所有权验证。
- 当前未提供找回密码流程。
- 当前限流适合早期规模，不替代边缘 WAF、Turnstile 和集中式滥用检测。
- 匿名产品仍需要举报、封禁、审计留痕和内容治理策略。
- 前端视觉匿名不能阻止用户在正文中主动发布个人信息。
