# 部署与发布指南

## 环境要求

- Node.js 22.13 或更高版本
- pnpm
- Cloudflare Workers 兼容运行时
- Cloudflare D1 数据库

## 本地开发

~~~bash
pnpm install
pnpm dev
~~~

访问 **http://localhost:3000**。开发前确认数据库绑定可用；认证和消息接口依赖 D1，不应以静态托管方式运行。

## 构建验证

~~~bash
pnpm lint
pnpm build
~~~

提交发布前至少完成一次生产构建，并手动验证：

- 注册、登录、刷新恢复与退出
- 六大板块到 36 个房间的导航
- 两个独立账号在同一房间按顺序收发消息
- 不同房间不会读取彼此消息
- 消息超出可视区域后的自动滚动
- 桌面、平板和手机宽度
- **/guide** 页面、视频播放与字幕

## 数据库迁移

Drizzle schema 位于 **db/schema.ts**，迁移文件位于 **drizzle/**。

~~~bash
pnpm db:generate
~~~

将迁移应用到目标 D1 数据库前，先备份生产数据并在预发布环境验证。不要把本地测试数据库、导出文件或账号数据提交到 Git。

## 托管配置

OpenAI Sites 项目配置位于 **.openai/hosting.json**。发布系统需要将 D1 binding 注入 Worker 运行时，应用通过服务端环境读取绑定。

## 发布策略

建议采用三阶段流程：

1. **Local**：完成类型、构建和交互验证。
2. **Preview**：使用独立 D1 数据库进行多用户与移动端回归。
3. **Production**：应用迁移、发布 Worker、执行冒烟测试并观察错误率。

生产回滚应同时考虑代码与 schema 兼容性。优先使用向后兼容迁移：先新增字段或表，再发布读取逻辑，最后清理旧结构。

## GitHub 仓库建议

- 默认分支：**main**
- 功能分支：**codex/feature-name** 或 **feature/name**
- 合并要求：构建通过、无敏感文件、文档与行为一致
- Release：使用语义版本，并在说明中标明迁移与已知限制

## 敏感信息检查

禁止提交：

- 邮箱账号、密码、Cookie 与会话令牌
- D1 数据库导出和真实用户消息
- API key、访问令牌与本地环境文件
- 构建缓存、部署压缩包和视频生成临时文件

发布完成后，访问线上登录页、聊天室和指南页完成最终冒烟测试。
